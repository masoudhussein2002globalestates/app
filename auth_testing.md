# Google and email authentication testing
Google redirects to auth.emergentagent.com with redirect derived from window.location.origin + /dashboard. Router detects session_id in useLocation().hash before any protected route. Backend exchanges it at https://demobackend.emergentagent.com/auth/v1/env/oauth/session-data with X-Session-ID. Sessions use httpOnly secure SameSite=None cookies and 7-day expiry. All identities use user_id UUID; no Mongo _id is serialized.

Test authenticated pages through email registration/login with temporary users. For Google browser testing when external login is unavailable, insert a user document and session in the configured Mongo database, matching user_id fields and using a future UTC expires_at; set session_token as a secure HTTP-only SameSite=None cookie for the preview hostname. Clearly distinguish session validation tests from actual Google provider login. Verify /api/auth/me, dashboard, create/edit/delete listing, uploads, favorites, bookings; a second user must get 404 when modifying another owner's property or requesting their payout. Anonymous writes must get 401. Logout must revoke the session. Clean up temporary test data. Never set a password or bypass login for the configured owner's email.
